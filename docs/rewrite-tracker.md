## Notification and search research notes

The notification design will persist a domain change and its notification intent in the same school-database transaction. A worker consumes committed intents with idempotent recipient/channel delivery records. This addresses the save-success/send-failure gap described in [AWS's transactional outbox guidance](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html). Delivery remains retryable; provider acceptance and confirmed delivery are separate states. Sender channel choices cannot bypass recipient permissions, school configuration or user preferences. This is a design requirement, not an implemented delivery service.

Global search queries school content with the viewer's current access resolved on every request, so there is no index to go stale when a relationship ends. It uses case-insensitive substring matches over names, titles, summaries and message bodies with prefix matches ranked first; PostgreSQL's [text-search index guidance](https://www.postgresql.org/docs/18/textsearch-indexes.html) remains the reference if a school outgrows sequential matching, and Arabic tokenisation would need measuring before adopting it. Snippets come only from fields the viewer could already read. See the global search checkpoint.

## Private file lifecycle checkpoint

Uploads are now judged by their bytes as well as their declared type. Binary formats must open with their signature (PDF, PNG, JPEG, GIF, WebP, the Office and OpenDocument containers, ZIP, MP3, M4A, MP4, WAV, WebM), and text formats must be UTF-8 without NUL bytes, with captions also carrying the WebVTT header; a unit test guarantees every accepted extension has such a rule. A configured ClamAV daemon receives every upload over its INSTREAM protocol before the file becomes ready; a match is refused and logged with its signature, and an unreachable daemon refuses the upload rather than passing it unscanned. A refused upload keeps its record with the reason and loses its bytes immediately, and a stored file records when it was scanned.

A sweep in each API replica rejects uploads left initiated for a day, deletes ready files nothing has referred to for a week and rejected records after a month. It finds references in the database catalogue, every foreign key to the file table and every json column, so documents such as site pages that carry media ids inside them keep their media without being listed anywhere. A file's row is locked while its references are rechecked, so a save that links it concurrently either finishes first and keeps the file or fails its foreign key rather than losing the link.

## Year lifecycle checkpoint

A school year now has a lifecycle separate from the default flag: it is planned, then taught, then closed. New years start in planning, so next year can be prepared while this one is taught, and the default can only be a year being taught, which the database enforces with a check constraint. Switching the default moves the flag in one transaction under the academic structure lock with the target's revision checked. A closed year keeps every read but refuses academic writes: attendance, assignment authoring, publishing, archiving and deletion, submissions, assessment, learning module and lesson authoring, and edits to the year's dates and terms all answer `academic_year.closed`. Corrections go through reopening, which needs its own capability (`years:reopen`, held by administrators by default and grantable through school roles) and a reason. Every activation, closing, reopening and default switch is recorded with its actor, and the year page shows that history.

Verification: the API regression moves a new year from planning to teaching, refuses skipping a step, a stale revision, making a planned year the default and closing the default year, closes a fixture year and sees attendance, assignment creation and a date edit refused, has a registrar role holding school management but not reopening refused, refuses reopening without a reason, reopens with one, records attendance again and reads both events with the reason. Switching the default runs through a fixture that calls the real switch inside a transaction and rolls it back, so the parallel browser projects never see another default: the planned year is refused, the active one becomes the only default, the former default's revision moves, the switch is recorded, closing the new default trips the constraint, and after the rollback the school's default is unchanged. The browser regression starts, closes and reopens a year from its card, sees the missing-reason refusal in the dialog, and reads the history on the year page.
